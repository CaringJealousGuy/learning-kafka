# Шаг 1
Создаём docker-compose.yml с необходимыми нам настройками. (см. комментарии внутри файла)

# Шаг 2
запускаем образы кафки командой
```
docker compose up -d kafka-1 kafka-2
```
# Шаг 3
Настраиваем топик выполнив команду 
```
docker exec kafka-1 /opt/kafka/bin/kafka-topics.sh --bootstrap-server kafka-1:29092 --create --topic messages --partitions 3 --replication-factor 2
```

# Шаг 4
Настройка продюсера и консьюмеров.
Настройка сериализации и десериализации сообщений.

Из классов я использую только пользовательский класс Message.
class Message:
    id: int
    text: str
    timestamp: str

Поле id - Номер сообщения
text - содержимое сообщения
timestamp - время отправки сообщения

# Шаг 5
Запуск приложения
Необходимо создать Dockerfile (см. комментарии внутри файла)
Выполнить команду
```
docker compose up -d --build --scale app=2
```
Эта команда скажет докеру собрать и подключить наше приложение в двух экземплярах


# Проверка работы
После запуска кластера спустя некоторое время (~10 Секунд) становится доступен web-ui. В котором перейдя в topics можно обнаружить наш топик "messages".
Зайдя в этот топик, будет видно, что сообщения приходят, и даже видно в какие партиции.
Отключив один из контейнеров кафки, можно обратить внимание, что в web интерфейсе, визуально подсветится, что один из броккеров перестал работать, но при этом процесс отправки сообщения от продюсеров к консюмерам не прекратился.
Если отключить и второй броккер, в таком случае при проверке логов приложений, можно обратить внимание на ошибки, которые будут говорить о том, что связь прервалась, но при включении любого из броккеров процесс возобновится и снова "встанет на рельсы".

Так же по логам так же можно посмотреть, какие именно приложения сейчас работают и увидеть, что оба броккера используются при работе.
