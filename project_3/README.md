# Message Filter App

Учебное приложение на Python и Faust для потоковой обработки сообщений в Kafka.

Приложение реализует две основные функции:

- блокировку пользователей;
- цензуру запрещённых слов.

Kafka и Kafka UI запускаются в Docker Compose, а Faust-приложение на этапе разработки запускается локально на компьютере.

### Kafka topics

#### `messages`

Входной topic приложения. В него отправляются все входящие сообщения.

Формат значения:

```json
{
  "sender": "Alice",
  "recipient": "Bob",
  "content": "Привет, Bob!"
}
```

#### `blocked_users`

Topic содержит события изменения списка блокировок.

Например, команда `/block Bob`, отправленная пользователем Alice,

```json
{
  "sender": "Alice",
  "recipient": "",
  "content": "/block Bob" 
}
```

превращается в событие:

```json
{
  "user": "Alice",
  "blocked_user": "Bob",
  "action": true
}
```

Для `/unblock Bob` используется `action: false`.

Topic не является самим текущим списком блокировок. Он хранит события, на основании которых Faust обновляет таблицу состояния.

#### `filtered_messages`

Выходной topic приложения. Сюда попадают сообщения после обработки.

В него могут попасть:

- обычные сообщения после цензуры;
- системные сообщения, например уведомление о блокировке или невозможности доставки.

## Faust Tables

### `blocked_users_table`

Персистентное состояние списков блокировок.

Логически таблица выглядит так:

```text
Alice -> [Bob, Charlie]
Bob   -> [Alice]
```

Ключом является пользователь, значением — список пользователей, которых он заблокировал.

Таблица использует RocksDB:

```python
store="rocksdb://"
```

Поэтому состояние сохраняется локально, а Faust также использует Kafka changelog для восстановления таблицы.

### `forbidden_words_table`

Персистентное множество запрещённых слов.

В качестве ключей хранятся сами слова:

```text
idiot  -> None
stupid -> None
```

Значение не используется. Важен сам факт наличия ключа в таблице.

## Классы

### `Message`

Описывает пользовательское сообщение:

- `sender` — отправитель;
- `recipient` — получатель;
- `content` — содержимое сообщения.

### `BlockUserEvent`

Описывает изменение списка блокировок:

- `user` — пользователь, изменяющий свой список блокировок;
- `blocked_user` — пользователь, которого блокируют или разблокируют;
- `action` — `true` для блокировки и `false` для разблокировки.

## Основная логика

### Цензура

Функция `censor_message()` разделяет текст на слова и проверяет каждое слово по ключам `forbidden_words_table`.

Если слово запрещено, оно заменяется последовательностью `*` той же длины.

Например:

```text
You are an idiot
```

при наличии `idiot` в таблице превращается в:

```text
You are an *****
```

### Команды администратора

Сообщение от пользователя `ADMIN` рассматривается как административная команда.

Добавление слов:

```text
/addword idiot stupid
```

Удаление слов:

```text
/removeword idiot stupid
```

Команда изменяет `forbidden_words_table` и не отправляется дальше как обычное пользовательское сообщение.

### Блокировка пользователей

Команда:

```text
/block Bob
```

создаёт событие в topic `blocked_users`.

Затем `process_blocked_users` обновляет `blocked_users_table`.

Разблокировка:

```text
/unblock Bob
```

создаёт событие с `action: false`, после чего Bob удаляется из списка блокировок пользователя.

### Фильтрация входящего сообщения

Для обычного сообщения сначала определяется отправитель и получатель.

Проверка выполняется по правилу:

```python
sender in blocked_users_table[recipient]
```

Если отправитель заблокирован получателем, исходное сообщение не отправляется получателю. Вместо него в `filtered_messages` отправляется системное уведомление отправителю.

Если блокировки нет, сообщение проходит через цензуру и отправляется в `filtered_messages`.

## Запуск проекта

### 1. Запустить Kafka и Kafka UI

Запустите инфраструктуру из `docker-compose.yml`:

```powershell
docker compose up -d
```

В текущей конфигурации Faust ожидает Kafka на:

```text
localhost:9092
```

Kafka UI обычно доступен через порт, настроенный в Compose-файле.

### 2. Установить зависимости Python

Создайте виртуальное окружение и установите Faust Streaming:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install faust-streaming
```

Если виртуальное окружение уже создано, этот шаг повторно выполнять не нужно.

### 3. Создать topics

Необходимы следующие topics:

```text
messages
blocked_users
filtered_messages
```

Для текущей учебной конфигурации используется одна partition для основных topics и Faust Tables.

### 4. Запустить Faust

Из каталога с `app.py`:

```powershell
faust -A app worker -l info
```

После запуска Faust создаст необходимые внутренние topics для своих Tables.

## Тестирование

Для тестирования удобно использовать Kafka UI и отправлять JSON непосредственно в topic `messages`.

### 1. Проверка обычного сообщения

Отправить:

```json
{
  "sender": "Alice",
  "recipient": "Bob",
  "content": "Hello Bob!"
}
```

Ожидаемый результат: сообщение появляется в `filtered_messages` без изменений.

### 2. Добавление запрещённого слова

Отправить от имени администратора:

```json
{
  "sender": "ADMIN",
  "recipient": "ADMIN",
  "content": "/addword idiot"
}
```

После этого слово `idiot` должно присутствовать в `forbidden_words_table`.

### 3. Проверка цензуры

Отправить:

```json
{
  "sender": "Alice",
  "recipient": "Bob",
  "content": "You are an idiot"
}
```

Ожидаемый результат в `filtered_messages`:

```text
You are an *****
```

### 4. Добавление нескольких запрещённых слов

```json
{
  "sender": "ADMIN",
  "recipient": "ADMIN",
  "content": "/addword idiot stupid badword"
}
```

Все три слова должны попасть в таблицу.

### 5. Удаление запрещённого слова

```json
{
  "sender": "ADMIN",
  "recipient": "ADMIN",
  "content": "/removeword idiot"
}
```

После удаления `idiot` больше не должен заменяться при цензуре.

### 6. Блокировка пользователя

Alice блокирует Bob:

```json
{
  "sender": "Alice",
  "recipient": "Alice",
  "content": "/block Bob"
}
```

Это должно создать событие в `blocked_users`, после чего `blocked_users_table` для Alice должен содержать Bob.

### 7. Проверка блокировки

Bob отправляет Alice сообщение:

```json
{
  "sender": "Bob",
  "recipient": "Alice",
  "content": "Hello Alice!"
}
```

Ожидаемый результат: Alice не получает исходное сообщение. В `filtered_messages` появляется системное сообщение для Bob:

```text
Сообщение не было отправлено: пользователь ограничил круг лиц.
```

### 8. Разблокировка пользователя

Alice отправляет:

```json
{
  "sender": "Alice",
  "recipient": "Alice",
  "content": "/unblock Bob"
}
```

После этого Bob снова может отправлять Alice сообщения.

## Полный сценарий проверки

Рекомендуемый порядок:

1. Добавить запрещённое слово `idiot`.
2. Отправить Alice сообщение Bob с этим словом и убедиться, что слово замаскировано.
3. Alice выполнить `/block Bob`.
4. Bob отправить Alice сообщение и убедиться, что оно не доставляется.
5. Alice выполнить `/unblock Bob`.
6. Повторить отправку сообщения от Bob к Alice и убедиться, что оно снова проходит.
7. Удалить `idiot` через `/removeword idiot` и проверить, что слово больше не маскируется.

## Ограничения текущей версии

Это учебная реализация. Она не содержит:

- отдельной системы регистрации пользователей;
- настоящей аутентификации администратора;
- отдельного topic для запрещённых слов;
- обработки всех возможных ошибочных команд;
- сложного разбора пунктуации и вариантов написания запрещённых слов.

Идентификатор `ADMIN` используется только для упрощённой эмуляции администратора.
